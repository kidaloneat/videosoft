# Video Bot — сборка ролика из 200 сцен

Берёт готовый файл сцен (промпт + текст на каждую из ~200 сцен) и один цельный
аудиофайл озвучки → генерирует картинки через Atlas Cloud (GPT Image 2) →
собирает готовый .mp4 с лёгким Кен-Бёрнс зумом (5–7%), субтитрами и звуком,
готовый к заливке на YouTube.

## Два способа пользоваться

1. **Веб-интерфейс** (`app.py`) — открываешь страницу в браузере на телефоне,
   загружаешь файл сцен + аудио, ждёшь прогресс-бар, скачиваешь готовое видео.
   Это то, что тебе нужно для повседневной работы с iPhone.
2. **CLI** (`main.py`) — то же самое из терминала, для отладки на сервере.

В обоих случаях сама обработка (Atlas Cloud + ffmpeg) должна выполняться на
сервере — на iPhone это физически не запустить. Практичный вариант — дешёвый
VPS (Timeweb, Selectel и т.п. — раз ты в Питере, так будет удобнее по оплате).
Веб-интерфейс как раз и нужен, чтобы с телефона просто открыть страницу в
браузере, а вся тяжёлая работа шла на сервере в фоне.

## Вариант без сервера, без ноутбука и без телефона при регистрации — Render.com

Если не хочешь подтверждать телефон (как требует Replit), есть Render.com —
бесплатный тариф для веб-сервисов, регистрация только по email/через GitHub,
без номера телефона. В архиве уже есть `Dockerfile` — он гарантирует, что
ffmpeg будет установлен, независимо от того, что предлагает хостинг по
умолчанию.

**Шаги:**

1. Заведи аккаунт на **github.com** (только email, без телефона). Создай
   новый репозиторий (New repository → Public или Private — не важно) и
   загрузи туда все файлы из архива через кнопку "Add file → Upload files"
   прямо в браузере (можно и с iPhone, но удобнее с компьютера — если он
   есть под рукой хотя бы на 10 минут для загрузки).
2. Заведи аккаунт на **render.com** — можно сразу через "Sign up with
   GitHub", это займёт один клик и не потребует телефон/карту для
   бесплатного веб-сервиса.
3. **New + → Web Service** → выбери свой репозиторий → Render сам увидит
   `Dockerfile` в корне и предложит собрать через Docker (важно выбрать
   именно Docker-окружение, а не "Python", иначе ffmpeg может не
   установиться).
4. В разделе **Environment** добавь переменные:
   - `ATLASCLOUD_API_KEY` → твой ключ
   - `APP_PASSWORD` → свой пароль
5. Нажми **Create Web Service** — через несколько минут (первая сборка
   Docker-образа) появится публичный адрес вида
   `https://videobot-xxxx.onrender.com` — открывается в Safari на iPhone.

**Важно про бесплатный тариф Render:** сервис "засыпает" после 15 минут без
входящих запросов и просыпается ~30-60 секунд при следующем открытии. Пока
идёт обработка ролика — держи страницу прогресса открытой в Safari: она сама
каждые пару секунд стучится на сервер, и это не даёт ему уснуть посреди
рендера 200 сцен.

## Вариант без сервера и без ноутбука, но с подтверждением телефона — Replit

Если не хочешь ни арендовать VPS, ни держать включённым ноутбук — можно
развернуть бесплатно на [replit.com](https://replit.com), прямо через браузер
на телефоне. В архиве уже есть нужные файлы конфигурации (`.replit`,
`replit.nix`) — они говорят Replit поставить Python и ffmpeg автоматически.

**Шаги:**

1. Зарегистрируйся на replit.com (можно через Google-аккаунт).
2. Create Repl → выбери "Import from local files" (или "Upload folder") →
   загрузи содержимое архива `videobot.zip`.
3. Слева в панели найди раздел **Secrets** (значок замка) и добавь две
   переменные — так ключи не попадут в код и останутся приватными:
   - `ATLASCLOUD_API_KEY` → твой ключ с atlascloud.ai
   - `APP_PASSWORD` → свой пароль для входа в веб-интерфейс
4. Нажми зелёную кнопку **Run**. Через пару минут (первый запуск ставит
   зависимости) Replit покажет окно с адресом вида
   `https://videobot.твой-юзернейм.repl.co` — это и есть публичная ссылка,
   открывается прямо в Safari на iPhone.

**Особенности бесплатного тарифа:**
- Repl "засыпает" после нескольких минут без запросов — первое открытие
  страницы после паузы может занять 10-20 секунд, это нормально.
- Если рендеришь длинный ролик (200 сцен) — держи вкладку с Replit открытой
  или изредка обновляй, чтобы Repl не "уснул" посреди обработки.
- Бесплатных вычислительных ресурсов достаточно для этого пайплайна, но при
  большой нагрузке (несколько роликов подряд) может понадобиться платный
  тариф Replit ($ в месяц) — обычно это дешевле самого дешёвого VPS.


1. Python 3.10+ и **ffmpeg**:
   ```bash
   sudo apt update && sudo apt install -y ffmpeg python3-pip
   ```
2. Скопировать эту папку на сервер (`scp`, `git`, через FTP — как удобно) и
   поставить зависимости:
   ```bash
   pip install -r requirements.txt --break-system-packages
   ```
3. Задать переменные окружения:
   ```bash
   export ATLASCLOUD_API_KEY="твой_ключ_с_atlascloud.ai"
   export APP_PASSWORD="придумай_пароль"   # обязательно — иначе кто угодно
                                            # в интернете сможет открыть твою
                                            # страницу и тратить твои деньги
                                            # на генерацию картинок
   ```
4. Запустить веб-сервер:
   ```bash
   python3 app.py
   ```
   По умолчанию слушает `0.0.0.0:8000`. Открываешь с телефона
   `http://IP_сервера:8000`, вводишь пароль из `APP_PASSWORD` — готово.

### Чтобы сервер не падал при закрытии SSH-сессии

Самый простой способ:
```bash
nohup python3 app.py > app.log 2>&1 &
```
Надёжнее — через systemd (гуглится как "python flask systemd service"), но
для личного инструмента `nohup` + `screen`/`tmux` вполне достаточно.

### Если хочешь открыть без прямого IP:PORT

Повесь nginx как reverse-proxy на 80/443 с обычным сертификатом (Let's
Encrypt) — тогда с телефона открывается по-человечески через `https://`. Это
отдельная небольшая настройка, могу расписать подробно, если понадобится.

## Формат файла сцен

CSV (`scenes.csv`) с тремя колонками — `scene`, `prompt`, `text`:

```csv
scene,prompt,text
1,"chibi character in suit, intro shot","Привет! Сегодня разберём пять ошибок..."
2,"chibi character pointing at falling chart","Первая ошибка — тратить больше..."
...
200,"...","..."
```

Либо JSON-список объектов с теми же тремя полями. Если у тебя другие названия
колонок — поправь `FIELD_ALIASES` в `scenes_loader.py`, остальной код трогать
не нужно.

`text` — это одновременно и то, что должно звучать в озвучке этой сцены
(нужно только для расчёта длительности показа картинки), и то, что попадёт
в субтитры. Отдельно передавать субтитры не нужно.

## Референсы персонажа и стиля (необязательно)

Если в веб-интерфейсе загрузить одну или несколько референсных картинок
(поле "Референсы персонажа и стиля"), каждая сцена будет генерироваться не
с нуля по одному тексту, а через режим **Edit** GPT Image 2
(`openai/gpt-image-2/edit`) — модель ориентируется на внешний вид персонажа
и общую стилистику с этих референсов, комбинируя их с описанием конкретной
сцены из `prompt`.

Практически это значит:
- Загрузи 1 фото — лист персонажа (то, что ты присылал: анфас/профиль/спина
  в чёрном костюме) и, если хочешь, ещё 1-3 кадра, задающих атмосферу/стиль
  сцен (плоские тени, цветовая палитра, толщина обводки и т.п.).
- В `prompt` каждой сцены теперь не обязательно заново расписывать внешность
  персонажа ("белая голова, чёрный костюм, красный галстук...") — это уже
  задают референсы. Пиши только то, что происходит и где: "персонаж сидит в
  лимузине, смотрит в телефон, ночной город за окном".
- Референсы загружаются на сервер Atlas Cloud **один раз** в начале обработки
  ролика и переиспользуются для всех сцен — платишь не за референсы, а
  только за сами генерации сцен.
- Максимум 10 референсных картинок за раз (ограничение самого API) — в
  большинстве случаев хватит 1 персонажа + 2-3 стилевых кадра.

Если референсы не загружать — всё работает как раньше, через обычный
text-to-image по одному только `prompt`.

## Запуск через веб-интерфейс

Открываешь `http://адрес_сервера:8000` с телефона → вводишь пароль → на
главной странице:
- название ролика (необязательно, просто для истории);
- файл сцен (.csv или .json);
- аудиофайл озвучки.

Жмёшь «Собрать видео» → попадаешь на страницу прогресса, которая сама
обновляется каждые пару секунд (можно закрыть телефон и вернуться позже —
обработка идёт на сервере, а не в браузере). Когда готово — кнопка
«Скачать видео».

## Запуск через терминал (CLI)

```bash
python3 main.py --scenes scenes.csv --audio voiceover.mp3
```

Результат — `jobs/cli/output/final.mp4`.

В обоих случаях скрипт:
1. Сгенерирует недостающие картинки (уже готовые — пропустит, так что можно
   спокойно перезапускать после обрыва сети, деньги за повторную генерацию
   не спишутся).
2. Посчитает длительность каждой сцены по количеству слов в `text`,
   промасштабирует так, чтобы сумма точно совпала с длиной аудиофайла.
3. Отрендерит зум-клипы, склеит, наложит субтитры, вмонтирует звук.

На 200 сценах основное время съедает шаг 1 (генерация картинок) — зависит от
конкурентности (`ATLAS_CONCURRENCY` в `config.py`, по умолчанию 5 параллельных
запросов) и очереди на стороне Atlas Cloud.

## Важное про синхронизацию звука

Аудио у тебя — один цельный файл на весь ролик, без таймкодов по сценам.
Поэтому длительность каждой сцены — это **оценка** по количеству слов
(средний темп ~155 слов/мин, настраивается в `config.py` →
`WORDS_PER_MINUTE`), а не точная привязка к реальным паузам в озвучке.
Сумма всех сцен всегда точно равна длине аудио, но **внутри** ролика возможен
небольшой дрейф в пару сотен миллисекунд на сцену, если бот озвучивает
что-то быстрее/медленнее среднего. Для коротких сцен (5-15 сек) это обычно
незаметно на слух.

Если через какое-то время захочешь точную синхронизацию — следующий шаг:
прогонять `voiceover.mp3` через распознавание речи (Whisper) и матчить
таймкоды слов с текстом каждой сцены. Это отдельная, более тяжёлая доработка,
закладывать её сразу не стал, чтобы не усложнять первую рабочую версию.

## Что настраивается в `config.py`

- Размер и качество картинок Atlas Cloud (`ATLAS_IMAGE_SIZE`, `ATLAS_QUALITY`)
- Разрешение и FPS итогового видео
- Амплитуда зума (`ZOOM_MIN_PCT` / `ZOOM_MAX_PCT`, сейчас 5-7% как просил)
- Шрифт, размер и позиция субтитров
- Минимальная длительность показа одной картинки (`MIN_SCENE_SEC`)

## Стоимость на один ролик (200 сцен)

- Без референсов (обычный text-to-image, GPT Image 2): **$0.008 за картинку**
  (medium quality, 1536×1024) → 200 картинок ≈ **$1.6**.
- С референсами (режим Edit, GPT Image 2): **$0.01 за картинку** → 200
  картинок ≈ **$2**. Загрузка самих референсных файлов бесплатна.

Платишь только за реально сгенерированные картинки — повторные попытки при
сетевых сбоях ретраятся автоматически и не дублируют оплату за уже успешные
сцены.

## Структура проекта

```
config.py          — все настройки в одном месте
scenes_loader.py    — парсинг файла сцен (CSV/JSON)
atlas_client.py      — генерация картинок через Atlas Cloud, с ретраями
timing.py            — расчёт длительности сцен под длину аудио
subtitles.py          — генерация .ass субтитров
render.py              — ffmpeg: зум-клипы, склейка, субтитры, звук
pipeline.py             — вся сборка как одна функция с прогресс-коллбэком
main.py                  — CLI-обёртка над pipeline.py
app.py                    — веб-интерфейс (Flask) над pipeline.py
templates/, static/        — HTML/CSS веб-интерфейса
Dockerfile, .dockerignore   — для деплоя на Render/Railway/Fly.io (гарантирует ffmpeg)
.replit, replit.nix          — для деплоя на Replit
test_pipeline.py               — тест сборки на 5 фейковых сценах без Atlas Cloud
```
